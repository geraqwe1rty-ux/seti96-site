# Исправление доставки teplo.seti96.ru, 22.10.2026

## Наблюдение

Посетитель получает «заявка сохранена, доставка не подтверждена». Браузерная доставка зависит от доступности внешнего домена chatgpt.site у посетителя. Проверка от 20 октября подтверждала только успешную единичную отправку из тестового браузера. Причина недоступности шлюза у конкретного посетителя по снимку не установлена.

## Подготовленное изменение

При настроенных TELEGRAM_BOT_TOKEN и TELEGRAM_CHAT_ID форма работает через собственный сервер. Он сохраняет заявку с fsync, отправляет уведомление, повторяет неудачные отправки с увеличением интервала от 30 секунд до часа. Очередь перечитывается при запуске; для сохранности после перезапуска DATA_DIR должен находиться на постоянном томе. Подтверждённые заявки повторно не отправляются при обычном повторном запросе. При потере ответа Telegram возможен дубль: Telegram sendMessage не предоставляет сквозной idempotency.

Пользователю отдельно сообщается подтверждённая доставка или сохранение в очередь. Событие Метрики lead_sent отправляется только после подтверждения, lead_accepted означает очередь. При отсутствии серверных настроек текущий браузерный маршрут временно сохранён. Старые заявки с браузерной квитанцией автоматически не переотправляются, чтобы не дублировать ранее полученные обращения. Заявки без доставки нужно проверить в защищённой админке после получения доступа.

Поддерживается штатный ответ Telegram migrate_to_chat_id при переносе группы. Токен не помещается в исходники или клиентский код.

## Условия запуска

В приложении Сети96 в Timeweb проверить:

1. TELEGRAM_BOT_TOKEN существующего бота и TELEGRAM_CHAT_ID существующей группы (последний известный ID -1004458806694).
2. DATA_DIR на постоянном томе. Один экземпляр Node-приложения обслуживает эту файловую очередь.
3. Исходящий HTTPS к api.telegram.org:443 и права бота писать в группу.
4. Развёртывание актуального коммита. После этого отправить одну явно помеченную тестовую заявку через форму и подтвердить Telegram. Отдельно проверить очередь при временном сбое.

23 изолированные проверки прошли: сохранение перед отправкой, ошибки диска, параллельные обращения, повтор после перезапуска, отсутствие ложного подтверждения и совместимость существующих обработчиков. Это не проверка доставки на рабочем сервере.

На момент подготовки доступ к панели Timeweb из среды агента отсутствует. Секреты и постоянство DATA_DIR не проверены. Исправление не считать запущенным до проверки серверных настроек и реальной доставки.
